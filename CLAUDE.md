# Astro knowledge base — rules

Rules version: see `conventions.yaml` (`version:`). Owner: Sahar Shahaf. Only the
owner changes these rules (enforced by `.github/CODEOWNERS`).

## What this is

A shared knowledge base for the group, read in Obsidian and searched with Claude. It has
three parts. **This repository is public; the two Keeper libraries are closed** (group
members only).

| Part | Holds | Who writes |
|---|---|---|
| **This git repository** (the skeleton, public) | Rules, conventions, templates, scripts, skills, code pins | The owner; members propose changes by pull request |
| **Keeper library "astro-kb-data"**, synced to `keeper/` | PDFs, data, parsed documentation, search indexes, `generated/` notes, `locks/`, `roles.yaml` (the curators) | Curators and the owner; members read only |
| **Keeper library "astro-kb-notes"**, synced to `live/` | The notes: one folder per topical **arm**, plus the shared `papers/`, `code/` and `requests/` | Members |

Notes are live: Keeper syncs them to everyone within minutes. The owner commits
snapshots of them to a separate, **private** repository from time to time
(`scripts/snapshot_notes.py`).

## Hard rules

1. **No proprietary data.** Never open, copy or store unreleased Gaia data or internal
   DPAC documents. Public material only: released documentation, demo files, published
   papers. **Nothing private goes into git:** no notes, data, PDFs, member names, e-mail
   addresses or tokens. `scripts/check_public.py` refuses them.
2. **One writer per file.** Only the note's `author` changes a note. To answer, add a
   discussion file (`templates/Discussion.md`). To replace, write a new note with
   `supersedes:`. Two people writing the same file make a Seafile conflict copy.
3. **Drafts go to `outbox/`, then `/publish`.** Never write a new note straight into
   `live/`: anything saved in `live/` is shared at once. `/publish` runs the checks and
   moves the draft into `live/`.
4. **Never edit generated files** (`keeper/generated/`, or `generated: true` in the
   frontmatter). Only the index keeper reruns the scripts that make them.
5. **Papers: curators ingest, members request.** A member asks with `/request-paper`. A
   curator (listed in `keeper/roles.yaml`) adds papers with `/ingest`, after checking that
   they are public.
6. **Label AI-generated text** with a callout naming the model and date:
   `> [!note] Generated by <model> on <YYYY-MM-DD>.`
7. **The skeleton changes only by pull request.** Never push to `main`. Use `/share`.
   Run `python scripts/check_vault.py` and `python scripts/check_public.py --staged`
   first; CI runs both on every pull request.
8. **Code repositories are read-only.** They are cloned in `external/` at the commit
   pinned in `sources.yaml`; changes go to the code repository itself.
9. **Calculations and notebooks go in `sandbox/`** (local, never shared). A result worth
   keeping becomes a note (through `outbox/`) or a data product (through a curator).
10. **Gaia column names, types, units and flag bits** come from the structured data model
    (`lookup_column`, `find_columns`), never from memory or a meaning-based search.

## Arms

An **arm** is a topical folder in `live/`, e.g. `live/binary-stars/`. The list, with each
arm's tags, is in `conventions.yaml`. Each arm has `notes/`, `lessons/`, `topics/` and
`discussion/`. A note lives in one arm; `arms:` in its frontmatter can name others.
Papers and code cards are shared by all arms. A paper's arms are the one its importer set
plus every arm whose notes cite it (generated).

**`gaia` is the foundation arm.** It holds what the Gaia data and documentation say:
column, flag and unit lessons, selection criteria, validation results, and (by label) the
Gaia Collaboration papers and the generated documentation. The science arms
(`binary-stars`, `milky-way`, `hot-stars`) hold the science and how it uses Gaia.

- **Links run one way: from a science arm into `gaia`.** A `gaia` note never links to a
  note of a science arm; the checker refuses it. A note that connects the two (e.g. a
  black-hole mass from a DR3 orbit) lives in the science arm.
- **The reverse view is generated.** `lookup_column` lists the notes of every arm that use
  a column (`applies_to:` or a link to the column), next to the papers and code.
- **Gaia tags** (`NSS`, `DataModel`, …) may be used in every arm.

File names are unique across all arms, so wikilinks `[[Title]]` work across arms.

## Search (MCP server `astro-kb`, started from `.mcp.json`)

- `lookup_column(table, column)`, `find_columns(text, table)`: exact Gaia column facts.
- `search_kb(query, source_type, author, arm)`: passages by meaning. Cite source and page/line.
  With no filter it searches everything (all arms, papers, code, documentation).
  `arm="<arm>"` keeps one topic (`arm="gaia"`: everything about Gaia: its notes, papers
  and documentation); `source_type="note" | "paper" | "code" | "docs"` keeps one kind of
  source (`"docs"`: the Gaia documentation only). One index, one embedding model; every passage is labelled with its arm.
- A question about a column and its uses: `lookup_column` for the table entry, then
  `search_kb` with no filter for how notes, papers and code use it.

## Layout

| Folder | Holds | In git |
|---|---|---|
| `live/<arm>/` | an arm's notes, lessons, topics, discussion | no (Keeper notes) |
| `live/papers/`, `live/code/`, `live/requests/` | paper notes, code cards, paper requests | no (Keeper notes) |
| `keeper/` | `pdfs/`, `data/`, `parsed/`, `index/`, `generated/`, `locks/` | no (Keeper data) |
| `outbox/` | your drafts, before `/publish` | no (local) |
| `sandbox/` | your calculations | no (local) |
| `index/`, `external/` | your search index, code checkouts | no (local) |
| `templates/`, `scripts/`, `.claude/`, `docs/` | templates, tools, skills, hooks, design | yes (public) |

## Note types

Every note has YAML frontmatter with `title`, `type`, `created`, `author`, `tags`. The
fields of each type and the allowed tags are in `conventions.yaml`;
`scripts/check_vault.py` checks them. File names replace `:` and `?` with `_`.
